# 会議室予約処理の修正

`src/room_booking/` には会議室の予約要求を処理する既存コードがあります。関連ファイルを調べ、公開関数 `room_booking.schedule(existing, requests)` を次の仕様に合わせて修正してください。

- `existing` は既存予約のリストで、各要素は `{"room": 文字列, "start": "HH:MM", "end": "HH:MM"}` です。
- `requests` は受付順に並ぶ要求のリストで、各要素は `{"id": 文字列, "room": 文字列, "start": "HH:MM", "end": "HH:MM", "priority": 0以上の整数}` です。IDは重複しません。時刻は同じ日の24時間表記で、常に start < end です。入力形式は正しいものだけが渡されます。
- 要求は優先度の**高い順**に処理し、同じ優先度では元の受付順を守ります。既存予約または先に受理した要求と、**同じ部屋で時間が重なる**要求は拒否します。異なる部屋なら同時刻でも受理します。
- 予約区間は半開区間 `[start, end)` です。前の予約の終了時刻と次の開始時刻が等しければ重なりません。
- 戻り値は `{"accepted": [受理したID, ...], "rejected": [拒否したID, ...], "calendar": {部屋名: [{"start": ..., "end": ...}, ...]}, "minutes_booked": {部屋名: 合計予約分数}}` です。`calendar` と `minutes_booked` は既存予約と受理した要求を含みます。各部屋の区間を開始時刻順に並べます。部屋名には既存予約・要求に現れたものをすべて含めます。分数は各区間の長さを足し、重複した既存予約があってもそのまま足します。
- `existing` と `requests`、その内部の辞書を変更しないでください。戻り値の区間辞書も入力から独立させてください。標準ライブラリだけを使ってください。公開テストは `python -m pytest -q public_tests -p no:cacheprovider` で実行できます。
