# 通知条件・優先順位・再送・配信停止の仕様書

同一リリースの要件を示す。ID順・一般則より具体則という理由だけで優先順位を付けない。例外は対象IDを明記した規定だけとする。
通知種別は販促・請求・セキュリティに分け、1件の通知は1種別だけに属する。請求の内訳も、月次請求発行・未払督促・支払完了確認のいずれか1種類とする。メールとSMSは別の送信チャネルである。
利用者の販促配信同意と、配信基盤の全体停止フラグは別の値である。通常の配信・再送の必須処理は全体停止フラグがオフの稼働中に適用する。稼働中でも販促配信同意を停止している利用者は存在する。
同じ利用者への異なる請求IDの未払督促と支払完了確認が、同じメール枠で同時待機するケースも存在する。1枠には最初に選ぶ1件だけを投入する。
新規の月次請求発行通知では、本文生成・重複防止キー登録・配信キュー投入は別の処理で、開始時点ではいずれも未完了とする。「後」は完了より厳密に後で、同時処理や過去の完了記録の流用は認めない。
以下の配信要求は受付時に宛先が正しい利用者のものと検証済みである。希望言語は日本語か英語のどちらか1つを記録する。
現地時刻は利用者の必須設定であるタイムゾーンから求める。配信キューへの投入と実際の送信は別で、送信抑止中もキューで待機できる。

- R01: 販促メールの配信同意を停止した利用者について、停止後に受け付ける販促メールは、優先度によらず配信キューへ一切投入しない。
- R02: 配信同意済み利用者へのセキュリティ以外のメールは、利用者の現地時刻22時から翌7時まで送信せず、次の7時以降に送信する。
- R03: 請求メール2件が同時待機し優先順位が決まっている場合、同じメール枠で最初に選ぶ1件は、必ず優先順位の高い通知にする。
- R04: 全体停止フラグがオンの場合、原則として通知を配信キューへ投入しない。ただしR19を例外とする。
- R05: 稼働中に受け付けた新規の月次請求発行通知について、受付後30秒以内に、本文生成・重複防止キー登録・配信キュー投入をそれぞれ必ず完了する。
- R06: 希望言語が日本語の利用者には、日本語テンプレートを使う。
- R07: メールで一時的な通信失敗が起きた場合、次の再送予定を失敗から5分後に設定する。成功通知の受領後はこの規定を適用しない。
- R08: メール送信の成功通知を受領して配信完了状態にした送信IDについて、それ以後に新たな再送予定を作成しない。
- R09: 内容が「似ている」販促通知は1件にまとめる。似ていると判定する項目・時間幅・類似度は、この仕様書では定めていない。
- R10: メールの生成済み本文はUTF-8で保存する。
- R11: SMSが一時的な通信失敗となり、まだ1回目の失敗で再送上限に達していない場合、次の再送予定時刻をその失敗時刻のちょうど60秒後に設定する。
- R12: 請求メールでは、未払督促の優先順位を、支払完了確認の優先順位より常に高く設定する。
- R13: 通知IDは通知ごとに一意とし、同じ通知の再送でも変更しない。チャネルの送信IDとは別のIDである。
- R14: 配信同意済み利用者へのセキュリティ以外のSMSには、現地時刻22時から翌7時までという送信抑止を適用しない。メールのR02とは別のチャネルである。
- R15: 全体停止フラグがオフで、販促メールの配信同意を停止した利用者について、停止後に受け付ける優先度P0の販促メールは、必ず配信キューへ投入する。
- R16: 新規の月次請求発行通知を配信キューへ投入できるのは、同じ通知の重複防止キー登録が完了した後だけとする。
- R17: 希望言語が英語の利用者には、英語テンプレートを使う。
- R18: SMSが宛先不存在という恒久的な失敗になった場合、その失敗を理由とする再送を予定しない。一時的な通信失敗とは区別する。
- R19: R04の例外として、アカウント侵害を知らせるセキュリティ通知は、全体停止フラグがオンでも配信キューへの投入を許可する。販促・請求通知にはこの例外を適用しない。
- R20: 同じ優先順位の請求メールが同時待機した場合、どちらを先に選ぶかは、この仕様書では定めていない。
- R21: 販促配信同意の変更履歴には、変更前後の値を追記し、過去の履歴を上書きしない。
- R22: 稼働中は、メールの送信IDごとに、初回受付から10分後に必ず新たな再送予定を作成する。10分より前に成功通知を受領して配信完了状態になっていても作成する。
- R23: 新規の月次請求発行通知の重複防止キーを登録できるのは、同じ通知の本文生成が完了した後だけとする。
- R24: R11と同じ、SMSの1回目の一時的通信失敗で再送上限に達していない場合、次の再送予定時刻をその失敗時刻のちょうど300秒後に設定する。
- R25: 未払督促と支払完了確認が同じ利用者の同じメール枠で同時待機した場合、最初に選ぶ1件は、必ず支払完了確認にする。
- R26: 配信イベントの記録には、イベントの発生時刻をUTCで保存する。
- R27: 新規の月次請求発行通知の本文生成を開始できるのは、同じ通知の配信キュー投入が完了して投入受付番号が返された後だけとする。
- R28: 宛先検証で別の利用者の宛先と判明した要求は受付時に拒否し、通常の配信要求として扱わない。
