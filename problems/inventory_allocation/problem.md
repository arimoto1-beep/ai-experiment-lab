# 注文の在庫引当プログラムの修正

`solution.py` には、倉庫の在庫を注文に割り当てる既存プログラムがあります。
通常の注文では動きますが、条件によって仕様に合わない結果になります。
既存コードを読み、公開関数 `allocate_orders(stock, orders)` を次の仕様に合わせて修正してください。
補助関数の変更は自由です。標準ライブラリだけを使い、編集は `solution.py` 内で完結させてください。
コードの実行はできないため、読んで動作を確認してください。

## 入力

- `stock`: 商品コード（文字列）を在庫数（0以上の整数）に対応させた辞書。
- `orders`: 注文のリスト。リストの並びが受付順です。各注文は次の辞書です。
  - `id`: 注文ID（空でない文字列）。同じ呼び出し内では重複しません。
  - `priority`: 優先度（0以上の整数）。値が大きいほど先に処理します。
  - `items`: 1件以上の明細のリスト。各明細は `{"sku": 商品コード, "quantity": 数量}`。
    商品コードは空でない文字列、数量は1以上の整数です。同じ商品の明細が複数あっても構いません。
- 空の在庫辞書、空の注文リストも有効です。商品コードと注文IDは大文字・小文字を区別します。
- すべてこの形式の入力が渡されます。不正な型や欠けたフィールドの検証は必要ありません。

## 処理規則

1. 優先度の降順で注文を処理します。同じ優先度なら受付順を守ります。
   注文IDの文字順は処理順に影響しません。
2. 注文内で同じ商品が複数の明細に分かれている場合、数量を合計して必要数を求めます。
3. その注文のすべての商品を、処理時点の在庫でまかなえる場合だけ受け付け、必要数を差し引きます。
   必要数と在庫が等しい場合も受け付けます。`stock` にない商品の在庫は0とします。
4. 1つでも商品が不足する注文は拒否します。拒否した注文によって在庫は一切減らしてはいけません。
   明細の順番によって合否や残在庫が変わってはいけません。
5. 拒否した注文があっても、次の注文の処理を続けます。先に受け付けた注文を取り消したり、
   注文を部分的に受け付けたり、受付件数を最大化するために処理順を変えたりはしません。

## 出力と入力の保持

次の3つのキーだけを持つ辞書を返してください。

```python
{
    "accepted": [受け付けた注文ID, ...],
    "rejected": [拒否した注文ID, ...],
    "remaining": {商品コード: 最終在庫数, ...},
}
```

- `accepted` と `rejected` は、それぞれ実際に処理した順番で並べます。
- `remaining` には元の `stock` のキーをすべて残します。在庫が0になった商品も残します。
  元の `stock` にない商品のキーは追加しません。辞書のキー順は問いません。
- 渡された `stock`、`orders`、注文辞書、明細辞書・リストは変更しないでください。
- `remaining` は独立した辞書として返します。呼び出し後に入力在庫や戻り値を編集しても、
  もう一方に影響しないようにしてください。複数回の呼び出しも独立です。

## 例

```python
stock = {"pen": 5, "pad": 2}
orders = [
    {"id": "Z", "priority": 1, "items": [{"sku": "pen", "quantity": 3}]},
    {"id": "A", "priority": 1, "items": [{"sku": "pen", "quantity": 3}]},
    {"id": "H", "priority": 2, "items": [{"sku": "pad", "quantity": 2}]},
]
allocate_orders(stock, orders)
# {"accepted": ["H", "Z"], "rejected": ["A"], "remaining": {"pen": 2, "pad": 0}}
# stock と orders は元のままです。
```
