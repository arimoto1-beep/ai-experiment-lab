## 判定

- 各レビューの肯定的な「仕様違反」指摘のみを既知不具合に照合する。現象に触れても無害・未確定と評価したものは発見に数えない。独立した原因ごとに1件とし、同じレビュー内での言い換えは集約する。
- 各方式の3件を集約して発見済み既知不具合のユニーク数、見落とした既知不具合数、誤指摘のユニーク数を数える。重複回数は同じ既知不具合を指摘したレビュー数から1を引いた総和。誤指摘も同じ原因なら集約する。根拠不足で正誤不明な提案は別欄に置き、誤りと断定しない。
- 既知以外の指摘は仕様文、公開可能な既存テスト、コードで再現可能なら確認済みの追加不具合に分類する。仕様と矛盾する、または再現条件が成立しない場合は誤指摘。未検証は別扱い。AIの自己評価を最終判定にしない。
- 観点の重複と不足は、各プロンプトが明示する仕様領域と実際に読んだファイル・指摘領域で判定する。React は入力/検証、UI/実行環境、ledger/出力状態、Python は入力正規化/注文集約、送料境界、出力/入力不変性を領域とする。担当を分けた結果、誰も触れなかった領域を列挙する。
- 実測の入力・出力・キャッシュ読取・書込・thinking トークン、CLI実行秒数を試行ごとに記録する。既存 `ai_lab.pricing` の Haiku 5.5 単価で API 換算費用を計算し、Cには設計費を加える。実請求額とは区別する。
