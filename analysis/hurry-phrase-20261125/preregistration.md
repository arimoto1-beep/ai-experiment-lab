## 疑問と仮説

Claude Haiku 5.5 への質問末尾に「急いで答えて。」を加えると、回答品質は下がるか。ここでの「品質」は、この10問に対する**指定形式での正答率**に限定する。仮説は、急かす表現で回答までの時間や出力トークンが減り、推論問題で正答率が下がる可能性がある、というもの。差がない結果や逆方向の結果もそのまま記録する。

## 問題と正解

[cases.json](cases.json) の算術・組合せ・包含排除10問と整数の正解を固定する。Q01〜Q03を簡単、Q04〜Q07を中間、Q08〜Q10を推論問題とする。#13 B26 と同一の問題群を用いるが、#14 の試行は新しい独立セッションで実施し、過去の回答をモデルに渡さない。正解は [verify_cases.py](verify_cases.py) の別計算で確認する。問題群の再利用と少数試行により、一般の回答品質への外挿はできない。

## 比較条件と試行数

- A: `質問文\n整数だけで答えてください。`
- B: `質問文\n整数だけで答えてください。\n急いで答えて。`
- モデルは `claude-haiku-5-5`、effort は `medium`。同じ固定 Docker CLI イメージ、分離認証 volume、CLI 引数、制限設定を使う。正解と採点コードをコンテナにマウントせず、モデルに渡さない。
- 各問題を A/B それぞれ2回、計40試行とする。各問題の第1反復は奇数IDで A→B、偶数IDで B→A、第2反復は逆順にする。各試行は別プロセス・別セッションとし、会話を引き継がない。失敗試行は置換しない。条件文以外を途中で変更しない。
- Docker コンテナは読取専用、権限削減、専用一時領域、ツールなし、MCPなし、セッション永続化なしとする。実行前に `claude.ai` のサブスクリプション認証を確認し、API 従量課金の環境変数を子プロセスへ渡さない。

## 時間・費用上限と停止規則

- 1試行60秒、`--max-turns 1`、CLI の `--max-budget-usd 0.01`。40試行のCLI予算上限合計は $0.40。開始後20分で新しい試行を開始しない。
- 2試行連続のタイムアウト、認証障害、実モデル不一致、安全境界違反で停止する。失敗や停止後の試行は再実行せず、完了・無効・未実施を区別する。CLI予算表示は実請求額ではない。

## 採点と分析

- CLI が正常終了し、実モデルIDが `claude-haiku-5-5` と照合できた試行を有効とする。最終回答の前後の空白・句点を除いた残りが整数1個なら正解と厳密比較する。説明や複数候補は形式違反で不正解とする。採点規則は結果に合わせて変更しない。
- 条件別の正答/有効試行、形式違反、問題別の正誤、ペア内のAのみ正解・Bのみ正解・双方正解・双方不正解を報告する。反復試行を独立した問題数と混同しない。難度別は記述的に示す。
- 壁時計時間、input/output/cache read/cache write/thinking トークンを記録し、条件別に集計する。thinking は output の内数とし二重加算しない。API換算費用は[Anthropic公式料金表](https://platform.claude.com/docs/en/about-claude/pricing)の基本単価（入力 $0.10、出力 $0.50、5分 cache write $0.125、1時間 cache write $0.20、cache read $0.01 / 100万トークン）で計算し、CLI報告費用と実請求額から区別する。単価の適用可否は実行前に確認する。
- 小規模な便宜問題群である。観測差を一般的・統計的な効果と解釈しない。差がなければ「この条件で低下を確認できなかった」と述べる。
