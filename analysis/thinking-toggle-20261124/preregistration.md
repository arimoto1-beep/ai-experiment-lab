# AI実験室 #13 B01 事前登録

固定日: 2026-11-24 JST。モデルへの最初の問題提示前に固定する。問いは「同じ Claude Haiku 5.5、同じ effort medium で Thinking の有効・無効だけを変えると、正答率、時間、トークン、API 換算費用は変わるか」。エフォート比較は B02 として別実験にする。

## 仮説と成立条件

- 仮説: 推論を要する問題では Thinking 有効条件の正答率が高くなる可能性がある。簡単な問題では差が小さく、有効条件の時間・出力トークン・API 換算費用が増える可能性がある。いずれも事前予測であり、成績の成功基準ではない。
- **実行ゲート:** 認証分離済みの Claude Code CLI から、Haiku 5.5 の Thinking を明示的に有効・無効へ切り替え、両条件で effort medium が変わらないことを検証できた場合にのみ問題試行を始める。単に thinking トークンが0だった、またはプロンプトで「考えないで」と指示しただけでは無効化の証拠にしない。
- ゲートを満たせない場合は全問題試行を未実施とし、正答率・時間・トークン・費用は比較不能と報告する。effort 変更、別モデル、従量課金 API キーへの移行で代用しない。

## 固定条件

- モデル `claude-haiku-5-5`、effort `medium`、日本語、各回新規 CLI プロセス、セッション永続化なし、ツールなし、`--safe-mode`。モデルに渡すのは問題文と「答えだけを1行で返してください。」だけ。正解と採点器はモデルに渡さない。
- 各問題につき Thinking 有効2回、無効2回。全6問、計24試行。順序は各問題で有効→無効→無効→有効とし、順序の偏りを軽減する。問題別の相関を残し、24件を独立した問題として扱わない。
- 1試行45秒、全試行の実行時間上限18分、CLI `--max-budget-usd 0.01` を各回に設定し合計 CLI 上限 $0.24。上限に達した試行は未完了として残し、追加試行しない。API 換算費用は使用量と実行日の公式単価から計算し、実請求額と区別する。
- CLI の終了状態、返答、実モデルID、使用量、Thinking 内訳、壁時計時間を保存する。モデルIDを照合できない試行は条件成績に含めず、無効試行として数える。タイムアウト・認証失敗も削除しない。

## 固定問題・正解

| ID | 区分 | モデルに渡す問題 | 正解 |
| --- | --- | --- | --- |
| Q1 | 簡単 | `17 + 28 はいくつですか。` | `45` |
| Q2 | 簡単 | `48 の 4 分の 3 はいくつですか。` | `36` |
| Q3 | 中間 | `21時47分の38分後は何時何分ですか。24時間表記で答えてください。` | `22時25分` |
| Q4 | 中間 | `7人が全員と1回ずつ握手すると、握手は合計何回ですか。` | `21` |
| Q5 | 推論 | `5台の機械が5分で5個の部品を作ります。同じ速さの100台が100分で作る部品は何個ですか。` | `2000` |
| Q6 | 推論 | `1から100までの整数のうち、3でも5でも割り切れないものは何個ですか。` | `53` |

## 採点・集計

- 最終回答を前後空白と句点を除いて正規化し、数値だけの回答は整数として比較する。Q3 は `22時25分` と `22:25` を同一とする。説明を含む回答は明確な答えが一つならその値を採点し、複数の異なる候補がある場合は不正解。採点規則は結果を見て変えない。
- 条件別の正解数/有効試行数、問題別の正誤、時間・入力/出力/キャッシュ/Thinking トークン、API 換算費用を示す。Thinking は出力トークンの内数として扱い、二重加算しない。無効試行数も条件別に示す。
- 小規模な便宜サンプルのため、有意差や一般的な効果を主張しない。差が0でも「効果なし」とは断定しない。失敗や未実施を成功数に混ぜない。

## 公開と停止

`docs/PUBLICATION_POLICY.md` と `AGENTS.md` に従い、正解、手順、集計、匿名化した回答と使用量を公開する。認証情報、CLI 生ログ、個人用絶対パスは公開しない。実行ゲート不成立、認証方式の変化、上限超過、モデル不一致、環境の安全境界の破れで停止し、原因を記録する。
