- A: `claude-haiku-5-5`、`--effort medium` を独立3回。指摘の和集合を人手・決定的処理で統合する。
- B: `claude-haiku-5-5`、`--effort high` を1回。
- C: `claude-opus-5-5`、`--effort high` を1回。公式モデル一覧に同IDがあり、分離CLIの事前確認でも同IDが示された。最終ストリームの実モデルIDで成否を再確認する。
- 各成果物に A1、A2、A3、B、C を1回ずつ、計15レビュー。失敗・timeoutも1回に数え、再試行しない。順序は X-A1, Y-A1, Z-A1, X-B, Y-B, Z-B, X-C, Y-C, Z-C, X-A2, Y-A2, Z-A2, X-A3, Y-A3, Z-A3。実行順による影響を避けるための固定順であり、他レビュー結果は渡さない。
- 各回に同じ公式課題文と同じ共通レビュー指示、同じ `list_files` / `read_file` のみを渡す。プロンプトは `TASK SPECIFICATION:\n{instruction}\n\nCOMMON REVIEW INSTRUCTIONS:\n{REVIEW_COMMON}\n\nPERSPECTIVE:\n{A_ROLE}`。`REVIEW_COMMON` と `A_ROLE` は `ai_lab/review_perspectives.py` の固定文字列を使い、ハッシュを記録する。特定欠陥に合わせた文面は使わない。
- 各回は新規CLIプロセス・`--no-session-persistence`・新規IPC volume・新規読取専用 worker。CLIには認証volumeとIPCのみ、workerには成果物と読取ツールのみをマウント。ネットワーク・Docker socket・書込ツールをworkerへ与えない。
- 全回600秒、35ターン、CLI予算上限 $2。Maxは使わない。上限による停止も成功扱いしない。
- API換算費用は2026-11-16に確認した Anthropic 公式料金で算出する。Haiku 5.5は input $0.10、output $0.50、1h cache write $0.20、cache read $0.01 / MTok。Opus 5.5はそれぞれ $4、$20、$8、$0.20 / MTok。実請求額ではない。Haikuの1リクエスト10万入力超の高価格帯はCLIの合算値だけでは確定できない場合、注記して基本料金推定とする。

## 採点

1. `findings` のうち場所・再現条件・実際と要求の差が具体的で、仕様とコードで確認できる指摘だけを発見として数える。`suspicions` は未確定として別記し、正解にも誤指摘にも入れない。
2. 同じ根本原因は表現・メッセージ数・レビュー回数によらず1件。独立した条件・修正責務は別件。Aは3回の確認済み指摘の和集合で数え、1回だけでも正しければ採用する。回別の指摘分布と重複回数も示す。
3. 既知14群への該当、見落とし、仕様またはコードと矛盾する誤指摘を分ける。根拠不足で確認できないものは未確定として別記する。
4. 既知外の指摘はコード・仕様・必要なら隔離した再現実験で検証し、確認済み新規、既知と同一、誤指摘、未確定に分類する。自己評価を判定に使わない。
5. 方式ごとに既知発見数、見落とし、誤指摘、新規、重複、実行時間、Aの合計処理時間、input / cache write / cache read / output / thinking、API換算費用、既知1件あたり費用を記録。発見0件なら1件あたり費用は算出不能とする。失敗回は費用・時間に含め、完了レビューの発見としては扱わない。
6. 費用は事前に揃えず、同一予算比較と呼ばない。誤指摘を含む品質で判断し、3成果物の小標本から一般的な性能差や因果を断定しない。

CLIのモデル一覧確認コマンドはレビュー前に行ったが、推論応答として扱われた可能性がある。課題・成果物・既知不具合は渡しておらず、15レビューの外側の補助呼び出しとして回数を別記する。使用量の構造化ログは取れなかったため、その費用は不明とする。
