# agentic_dev の認証・作業環境分離レビュー（2026-10-18）

実モデルと実際の認証トークンは使っていない。ダミー文字列だけを短命の Docker volume に置き、値は出力していない。既存の実験コードと課題には変更を加えていない。

## 現構成の確認結果

| 確認事項 | 現状 |
| --- | --- |
| 作業コマンドから認証を読めない | **不合格**。モデル用コンテナと同じマウント・UIDのコマンドから、ダミー認証ファイルを読めた。値は表示していない。 |
| 作業コマンドの不要な外部通信を止める | **未達**。モデル用コンテナは bridge ネットワークを共有する。固定された公開pytestコマンドも、モデルが編集した `src/` を実行する。 |
| CLI自身の認証・API通信 | **未検証**。ダミー認証では実サービスへの認証成功を証明できず、実モデル呼び出しは禁止されている。CLIのバージョンとコンテナのネットワーク経路は前回確認済み。 |
| 非公開テスト・元リポジトリの隔離 | **維持**。前回のDocker統合テストで、モデル用コンテナに両者が存在しないことを確認済み。 |
| ログへの認証情報の出力防止 | **不合格**。現在の `claude_stream.jsonl` はCLI出力をそのまま保存し、`_events` もツール出力を `history.json` に含める。ダミー文字列の保持をメモリ上で確認した。 |

認証ボリュームを読み取り専用にするだけでは、読み取りを防げない。モデルに許したBashコマンドが公開pytestだけでも、そのテストがモデルの編集したPythonを読み込むため、任意のコードが走り得る。モデル用コンテナ全体をネットワークなしにするとClaude CLIもAPIへ接続できない。

## 検討した小規模案

Claude Code内蔵のBash sandboxで、コマンドだけに認証ディレクトリの読取拒否と空のネットワーク許可リストを適用する案。公式資料は `sandbox.enabled`、`failIfUnavailable`、`allowUnsandboxedCommands: false`、`credentials.files` を提供している。Linuxでは `bubblewrap` と `socat` が必要で、Bash以外のファイルツールはこのsandboxの外側で動く。

一時イメージで `bubblewrap` の動作を確認した。現行Dockerのseccomp設定ではユーザー名前空間の作成が `EPERM` になり、検証用の `seccomp=unconfined` では起動できた。ダミー認証を隠し、子プロセスのネットワークを遮断できた。ただし公式資料は、コンテナ内で `/proc` を再利用する弱いnestedモードを案内し、親プロセス情報が子から見えると説明している。限定したダミー検査では `/proc` 経由のファイル読み取りは起きなかったが、網羅的な証明ではない。広いseccomp解除を本番設定として採用せず、Bash以外のファイルツールを含む境界も確認する必要がある。

## 推奨する構成変更

**Claude CLIコンテナと作業コンテナを分ける。** CLI側は専用認証ボリュームとAPI通信を持つが、課題の作業コピーをマウントしない。CLIの組み込みファイル・Bashツールは無効にする。モデルには固定されたMCPツールだけを見せ、固定コードのブリッジが共有Unixソケットを通じて作業コンテナへ要求を渡す。作業側は試行ごとの `src/` と読み取り専用の公開テストだけをマウントし、認証ボリュームも外部ネットワークも持たない。公開pytestは作業側で実行する。非公開採点は既存の別コンテナと採点コードを使い続ける。

この変更では、MCPの小さなサーバーとブリッジ、2コンテナの起動・終了管理、ツール出力を扱うログ処理、ダミー漏えいテストが必要になる。ツール名・形は従来の組み込みツールから変わるため、両モデルに同一の新条件を与え、実モデル開始前に課題と条件を再固定する。既存の課題、試行ディレクトリ、非公開採点、費用集計は再利用できる。構成変更が実験基盤に及ぶため、実装前にこの案と影響を報告する。

実装後の合格条件は、(1) ダミー認証を作業側のコマンド・ファイル操作・`/proc`・シンボリックリンク・環境変数から読めない、(2) 作業側からの外向き接続が失敗する、(3) ダミー認証を使うローカル模擬APIへのCLI通信が成功する、(4) 元リポジトリ・非公開テストの隔離が続く、(5) ダミー文字列が履歴・標準出力・標準エラー・結果JSONに残らない、の5点。実サービスでの認証成功はダミーだけでは証明できないため、後日、モデル呼び出しを許可された段階で別途確認する。
